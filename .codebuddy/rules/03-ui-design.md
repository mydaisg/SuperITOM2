# UI / UX 设计规范（SuperITOM2）

> 本规则始终注入。**改任何界面、任何弹窗、任何配色前，先读本规范。**

## 约束强度分级（必读，这是本规范的核心）

每条规范用符号标注约束强度，**AI 必须按强度执行，不得越级**：

| 符号 | 含义 | AI 应如何处理 |
|------|------|--------------|
| 🔴【硬性】 | 必须遵守，违反即返工 | 无条件执行 |
| 🟡【默认】 | 默认如此，有合理理由可偏离 | 偏离时须在回复中说明理由 |
| 🟢【偏好】 | 个人偏好/可复用参考 | 可参考，非强制，需结合场景判断 |

> **⚠️ 关键区分——「规范」与「举例」不是一回事**：
> 一条规则只有在明确标注 🔴/🟡 时才是约束；标注 🟢 或明确写了"示例/参考"的，**只是例子，禁止当成范本硬套**。
> 拿不准某条是规范还是举例时，**先问用户**，不要擅自套用。

## 一、全局风格（🔴 硬性）

- 主题：`shinytheme("cosmo")`。
- **UI 一致性是最高优先级**：任何新模块/新弹窗的风格，必须与既有模块统一，禁止引入新的视觉语言。
- 导航栏选中态：蓝色背景 `#337ab7`。
- 网络测试结果：暗色背景 `#1e1e1e`，成功绿色加粗、失败红色加粗。
- 状态用圆角彩色 badge 展示。

## 二、删除/危险操作确认机制（🔴 硬性）

统一采用「Confirm 机制三级实现」，全站推广，**禁止出现第四种确认样式**：

1. **基础模式**：单条删除的简单确认。
2. **子记录警告模式**：删除前提示存在关联子记录。
3. **批量删除模式**：绿/红色表格式确认界面（绿色=可安全删除，红色=存在关联/有风险）。

> 参考实现：角色管理模块的批量删除界面（绿/红表格式）。新模块的删除确认必须对齐此样式。

## 三、交互细节（🟡 默认）

- 全局拖拽弹窗：通过 `MutationObserver` 监听 `.modal-header` 实现，拖拽时标题栏显示 grab 抓手光标。
- 按钮风格：偏好**图标按钮**替代文字按钮（仅图标 + 悬浮提示，UI 紧凑化）。
- 搜索：支持 AND 多词搜索，标题优先高亮。

## 四、工单状态色（🔴 硬性，勿改）

| 状态 | 颜色 |
|------|------|
| 待处理 | `#f0ad4e` |
| 已派发 | `#5bc0de` |
| 处理中 | `#ff9800` |
| 已完成 | `#5cb85c` |
| 已关闭 | `#d9534f` |

## 五、配色/排版风格参考（🟢 偏好，仅作参考，非硬性规范）

> 以下是一套"红灰极简排版"风格参考，**它不是本项目的强制规范**，
> 仅当你需要做"文档/报告类页面"时，可作为风格选项之一。

- 主色红 `#E3120B`：仅用于线条和序号，**禁止铺底色**。
- 正文：`#2B2B29`（深灰），16px，行距 1.75，左对齐。
- 小标题：18px 特粗，左对齐，红色序号 01/02/03，下方 1px `#DDDDDD` 细线。
- 金句：22px 加粗，左对齐，左侧 2-3px `#E3120B` 竖线，无底色，全篇最大字。
- 整体原则：单一红色、少装饰，重点靠留白和线条引导。

> **使用前提**：只有在用户明确说"用那套红灰风格"时，才按此实现。
> 不要因为"见过这段规范"就默认套用到系统 UI 上。
